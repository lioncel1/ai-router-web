# AI Router 数据迁移方案

**版本：v0.8 Phase 1**

## 1. 目标

将 AI Router 当前分散的数据存储方式：

``` text
data/
├── gemini_conversations.json
└── chatgpt_conversations.json

logs/
└── router_calls.jsonl
```

逐步迁移到统一 SQLite 数据层。

迁移目标：

-   不影响 v0.7 已有功能。
-   保留历史 Conversation。
-   建立 Task 统一记录。
-   支持后续 Task Center 和 Workflow。

------------------------------------------------------------------------

# 2. 迁移原则

## 原则1：先新增，不删除

旧数据：

-   JSON
-   JSONL

保留作为备份。

SQLite：

-   新增
-   验证
-   逐步成为主数据源

------------------------------------------------------------------------

## 原则2：兼容优先

迁移过程中：

``` text
旧系统
+
SQLite
```

并行运行。

确认稳定后再降低旧系统依赖。

------------------------------------------------------------------------

## 原则3：可回滚

任何阶段失败：

-   停止SQLite写入。
-   恢复旧调用链。
-   保留已有数据。

------------------------------------------------------------------------

# 3. 当前数据分析

## Conversation数据

来源：

``` text
gemini_conversations.json
chatgpt_conversations.json
```

主要内容：

-   会话名称。
-   会话URL。
-   更新时间。
-   状态信息。

未来对应：

``` text
conversations
```

以及关联：

``` text
tasks
messages
```

------------------------------------------------------------------------

## 调用日志

来源：

``` text
logs/router_calls.jsonl
```

主要内容：

-   provider
-   action
-   success
-   duration
-   output
-   conversation_url

未来对应：

``` text
provider_calls
task_events
```

------------------------------------------------------------------------

# 4. 迁移阶段

## Phase 0：备份

执行：

``` text
备份现有data目录
备份logs目录
创建SQLite文件
```

目标：

确保任何时候可以恢复。

------------------------------------------------------------------------

# Phase 1：SQLite初始化

新增：

``` text
data/ai_router.db
```

创建：

``` text
tasks
messages
task_events
provider_calls
```

此阶段不改变业务逻辑。

验收：

-   数据库可以创建。
-   表结构正确。
-   服务启动正常。

------------------------------------------------------------------------

# Phase 2：双写模式

新的执行流程：

``` text
用户请求

↓

Task Manager

↓

创建Task(SQLite)

↓

调用Provider

↓

保存ProviderCall

↓

保存Message

↓

更新Task状态

↓

保留router_calls.jsonl
```

目标：

验证新数据链。

------------------------------------------------------------------------

# Phase 3：历史数据导入

## Conversation导入

读取：

``` text
gemini_conversations.json
chatgpt_conversations.json
```

生成：

-   Conversation记录。
-   历史URL绑定。
-   更新时间。

------------------------------------------------------------------------

## 日志导入

读取：

``` text
router_calls.jsonl
```

转换：

``` text
provider_calls
task_events
```

注意：

历史日志可能缺少完整Task上下文，因此：

-   能关联则关联。
-   缺失字段保留为空。
-   不伪造数据。

------------------------------------------------------------------------

# Phase 4：验证

检查：

## 数量

比较：

-   原日志数量。
-   SQLite记录数量。

## 功能

测试：

-   Chat
-   Auto
-   Dialogue

## 数据

确认：

-   Conversation可继续使用。
-   历史任务可查询。
-   服务重启数据存在。

------------------------------------------------------------------------

# Phase 5：切换主数据源

满足：

-   SQLite运行稳定。
-   新任务全部进入SQLite。
-   历史查询正常。

之后：

旧JSON：

仅作为备份。

旧JSONL：

仅作为审计备份。

------------------------------------------------------------------------

# 5. 回滚方案

## 数据问题

恢复：

``` text
旧JSON
旧JSONL
```

------------------------------------------------------------------------

## 代码问题

Git回退：

``` text
v0.8 commit
↓
v0.7 stable
```

------------------------------------------------------------------------

## 服务问题

停止SQLite写入：

恢复旧Gateway调用方式。

------------------------------------------------------------------------

# 6. 迁移验收标准

完成后：

-   SQLite成为任务主存储。
-   Chat任务可追踪。
-   Auto任务可追踪。
-   Dialogue任务可追踪。
-   历史Conversation保留。
-   服务重启不丢失任务。
-   v0.7功能无明显回归。
