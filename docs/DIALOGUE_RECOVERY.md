# Dialogue 续聊与异常恢复（v1.1）

## 一、常规续聊

1. 新建双模型 Dialogue，选择起始模型及目标消息条数。
2. 已完成 (`done`) 或安全停止 (`stopped`) 后，在界面点击“继续最近的对话”，或从任务中心选择历史 Dialogue 任务。
3. 系统依据已保存的最后一条模型回复确定下一位模型，并默认填入这条回复。可编辑内容、修改追加消息数。
4. 仅在明确点击“确认继续对话”后发送。原任务为终态，不会改写；续聊作为关联新任务持久化。

## 二、安全停止

运行中点击“停止对话”：若某个模型请求已经开始，该请求将继续至自然完成/失败，在检查点决定不再把结果发给另一模型。正常结束显示 `stopped`。**停止请求不是浏览器网络请求的撤销操作**。

## 三、失败任务与人工核对

- `failed` 任务不能直接当作可安全续聊节点；它的最后一条真实网页回答可能没有被写入数据库。
- 如果界面提供“核对网页回答并恢复”，程序只访问既有浏览器会话/消息，向用户展示候选回答。必须人工检查原网页确认**是当前轮次回复，且没有向下一个模型转发**，才保存恢复检查点。
- 确认后的恢复记录是单独 `stopped` 任务；不会把原失败任务涂改为 `done`。接着从新任务继续，下一模型应是候选回答的另一方。
- 原失败任务已有恢复记录时，任务中心显示恢复点和最新后续任务入口；系统拒绝重复创建同一恢复点。
- 缺少已发送证据、会话不一致、候选回答不明确、后续模型可能已收到消息等情况，**停止操作并人工核查**，而不是自动重发。

## 四、限制

- 恢复依赖当前仍可访问的 Gemini / ChatGPT 官方会话和浏览器登录状态。
- 富媒体正文提取和完成判定并非对所有官方页面都可靠；界面升级可能导致失败。
- SQLite 与浏览器会话 JSON 仍属两个存储；极端情况下会发生跨文件写入的部分成功，应谨慎人工核查。
- “查看/预览/核对”不发送模型请求；“确认继续对话”会调用实际模型网页。
